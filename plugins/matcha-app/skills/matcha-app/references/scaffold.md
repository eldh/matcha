# Scaffolding a new matcha app

Reference material for the `matcha-app` skill. Load this when creating a new
application from nothing. Everything here is the shape `bdiff` and `hog`
both landed on independently; they are structurally identical, so treat any
difference between them as an accident rather than a choice.

Substitute your app's name for `myapp` throughout, and `MyAppApp` for the
component module.

## The tree

```
myapp/
├── dune-project
├── myapp.opam          generated by dune - never hand-edited
├── .gitignore
├── install.sh
├── README.md  LICENSE
├── _opam -> /path/to/matcha/_opam     symlink, git-ignored (see below)
├── bin/    dune  main.re
├── lib/    dune  MyAppApp.re  + pure modules
└── test/   dune  Test.re  Input.re  Fixture.re  *_tests.re  run_tests.re
```

## Getting matcha available

Two options. The symlink is what both existing apps use, because it shares
one switch and picks up local matcha changes immediately:

```sh
ln -s /path/to/matcha/_opam _opam     # share matcha's local switch
```

Otherwise, a switch of your own with matcha pinned or installed:

```sh
opam switch create . 5.3.0
opam install matcha                          # the published package
opam pin add -y matcha https://github.com/eldh/matcha.git   # or track main
```

matcha needs OCaml >= 5.3.0, Reason >= 3.12.0 and ppxlib >= 0.36.0 (below
0.39.0). It does not build on Windows - the terminal layer needs `termios`
and `ioctl`.

## `lib/dune`

The load-bearing stanza.

```
; Everything real lives here so that test/app_tests.re can start the exact
; same component headlessly - the binary in bin/ is a thin launcher.
(library
 (name myAppApp)
 (wrapped false)
 (libraries matcha unix)
 (preprocess
  (pps matcha.ppx)))
```

- **`(preprocess (pps matcha.ppx))`** is what makes `[@component]` and JSX
  work. `matcha.ppx` is the public name; `ppx_component` is its internal
  name and only resolves inside the matcha repo itself.
- **`(wrapped false)`** so `bin/` and `test/` refer to `MyAppApp`, `Cli` and
  friends directly rather than through a wrapper module.
- **Add `threads.posix` if you run anything on a background thread.** matcha
  does not link threads itself, so it is not inherited.

## `bin/dune`

```
; Thin launcher. No JSX here, so no preprocess stanza.
(executable
 (name main)
 (public_name myapp)
 (libraries matcha myAppApp))
```

## `test/dune`

```
; The suites build real trees on disk and read them back, so nothing about
; them is cacheable on their source alone.
(test
 (name run_tests)
 (modules test input fixture cli_tests app_tests run_tests)
 (libraries matcha myAppApp unix)
 (deps
  (universe)))
```

Add `threads.posix` here too if a test touches `Thread` directly. Every
module in `test/` must be listed in `(modules ...)` **and** called from
`run_tests.re`, or it is silently never run.

## `bin/main.re`

Every failure path returns before `Runtime.start`, so an error prints on the
ordinary terminal instead of flashing the alternate screen.

```reason
/*
 * Everything real lives in the myAppApp library so test/app_tests.re can
 * start the exact same component headlessly. This file owns only what a
 * component cannot own itself: printing and exit codes.
 */

let printErr = (msg: string): unit => prerr_endline("myapp: " ++ msg);

let () =
  switch (Cli.parse(Sys.argv)) {
  | Cli.Help =>
    /* stdout and exit 0, so `myapp --help | less` works and a wrapper can
       tell "help was asked for" apart from "something went wrong". */
    print_string(Cli.usage);
    exit(0);
  | Cli.Invalid(msg) =>
    printErr(msg);
    exit(1);
  | Cli.Run(config) =>
    switch (preflight(config)) {
    | Error(msg) =>
      printErr(msg);
      exit(1);
    | Ok(state) =>
      Matcha.Runtime.start(~screen=Fullscreen, MyAppApp.app(~state, ~config))
    }
  };
```

Drop `~screen=Fullscreen` only if your frame is genuinely shorter than the
terminal. See the skill's rule 1.

## The app factory

At the bottom of `lib/MyAppApp.re`:

```reason
let app =
    (~state: State.t, ~config: Cli.config): (module Runtime.HooksComponent) =>
  (module
   {
     let make = () => Root.createElement(~state, ~config, ());
   });
```

Parameters, not globals: two headless handles in one test process must be
able to point at two different states. Parameterize over anything a test
needs to stub - a function that deletes files, a handle that does slow I/O.

If your root must be a bare `make` rather than a `[@component]` (see the
skill's root-component section), the factory looks like this instead:

```reason
let app = (~state, ~config): (module Runtime.HooksComponent) =>
  (module
   {
     let make = (): Element.t => {
       let quit = Event.useQuit();
       /* ... the whole root body ... */
     };
   });
```

## `test/run_tests.re`

```reason
let () = {
  print_endline("");
  print_endline("Running myapp tests");
  print_endline("===================");
  print_endline("");

  Cli_tests.run();
  App_tests.run();

  Test.finish();
};
```

Copy `Test.re` and `Input.re` from an existing app's `test/` directory -
matcha's own test helpers are not part of the installed package. See
`references/testing.md`.

## `install.sh`

```sh
#!/bin/sh
#
# Build myapp and copy the binary onto your PATH.
#
#   sh install.sh                 # build in the active switch
#   sh install.sh /path/to/matcha # build in that switch instead
#
# The BUILD needs an OCaml >= 5.3 switch with matcha available. The
# INSTALLED binary does not: it is self-contained, so it keeps working after
# you change switches.

set -e

here="$(cd "$(dirname "$0")" && pwd)"
dest="${MYAPP_BIN:-$HOME/.local/bin}"

if [ "$#" -ge 1 ]; then
  eval "$(opam env --switch "$1" --set-switch)"
else
  eval "$(opam env)"
fi

cd "$here"
dune build bin/main.exe
mkdir -p "$dest"
install -m 755 _build/default/bin/main.exe "$dest/myapp"

printf 'installed %s\n' "$dest/myapp"
```

## A CLI parser worth copying

Keep `parse` **pure** - `array(string) => parsed`, no I/O, no `~` expansion,
no existence checks - so tests call it with hand-built arrays and no
environment. All printing and exit codes live in `bin/main.re`.

```reason
type config = {pathArg: option(string), verbose: bool};
type parsed =
  | Help
  | Run(config)
  | Invalid(string);
```

Four grammar rules that are easy to miss and annoying to retrofit:

- A `--` sentinel ends option parsing; everything after it is positional.
- A `--help` **pre-scan** (stopping at `--`) so `myapp --bogus --help`
  prints help rather than erroring.
- `looksLikeOption(a)` is `String.length(a) > 1 && a.[0] == '-'`, so a bare
  `-` stays a positional argument.
- Every `Invalid` message ends with `try 'myapp --help' for usage.`

`bdiff/lib/Cli.re` and `hog/lib/Cli.re` are both about 150 lines and follow
this exactly.

## First run

```sh
eval $(opam env)
dune build
dune runtest
timeout 20 env MATCHA_HEADLESS=1 MATCHA_WIDTH=140 MATCHA_HEIGHT=40 \
  dune exec bin/main.exe < /dev/null
```

The dev profile promotes warnings to errors, so an unused binding fails the
build. Fix the code rather than suppressing the warning.
